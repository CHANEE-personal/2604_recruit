# 코드 리뷰 가이드

## 공통 검토 기준

- 테스트 코드 작성이 용이한 구조인지를 핵심 기준으로 판단
- **확장성** — 유연하게 대응할 수 있는 구조인지 검토
- **유지보수성** — 책임 분리, 변경 영향 범위 최소화, 코드 가독성
- 반복 코드가 있으면 풀어낼 방향성 제시
- 런타임 검증 필요 시 `runtime-guide.md` 참조

## 아키텍처 감지

패키지 구조를 먼저 분석하여 아키텍처를 판별한다.

| 판별 기준                                    | 아키텍처 | 상세                       |
|------------------------------------------|------|--------------------------|
| `adapter/`, `application/`, `domain/`    | 헥사고날 | `review-hexagonal.md` 참조 |
| `controller/`, `service/`, `repository/` | MVC  | `review-mvc.md` 참조       |
| 그 외                                      | 범용   | 책임 분리·의존 방향·테스트 용이성 위주   |

## 리뷰 등급

| 등급             | 의미                          |
|----------------|-----------------------------|
| **Must**       | 버그, 아키텍처 위반, 보안 이슈 — 반드시 수정 |
| **Should**     | 성능, 유지보수성 — 가급적 수정          |
| **Suggestion** | 더 나은 방향성 제안                 |
| **Nit**        | 오타, 스타일, 포매팅                |

이슈 없으면 `✅ 이슈 없음` 표기.

## 출력 형식

### 파일명 명시 리뷰

- 해당 파일만 리뷰, 연관 파일 리뷰 금지
- 네이밍·구조·런타임·개선점 등 파일 전체 검토
- 아래 상세 형식 사용

### 패키지 명시 리뷰

- 패키지 내 모든 파일 리뷰
- 먼저 요약 표 제시 후 상세 형식으로 설명

**요약 표 형식:**

| 파일명            | 등급   | 설명   |
|----------------|------|------|
| `Example.java` | Must | (내용) |

**상세 형식:**

```
### [등급] [파일명] 리뷰 제목

**Before:** (기존 코드)
**After:** (개선 코드)

설명: ...
개선 효과: ...
```
